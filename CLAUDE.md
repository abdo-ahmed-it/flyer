## Project Overview

Flyer is a Dart CLI tool that accelerates Flutter app development by automating repetitive tasks. It scaffolds project infrastructure, generates features, pages, forms, and models, and manages project resources.

## Development Commands

### Building and Testing
```bash
# Install dependencies
dart pub get

# Run the CLI locally during development
dart run bin/flyer.dart [command] [options]

# Format code
dart format .

# Analyze code
dart analyze

# Run tests (if available)
flutter test
```

### Publishing
```bash
# Dry run publish to check package
dart pub publish --dry-run

# Publish package
dart pub publish
```

## Architecture

### Entry Point
- **bin/flyer.dart**: CLI entry point using `args` package's `CommandRunner`
- Registers four main commands: `InitCommand`, `MakeCommand`, `FiendCommand`, `RunCommand`

### Command Structure
Each command in `lib/commands/` extends `Command` from the `args` package:
- **InitCommand**: Scaffolds project infrastructure (features, theme, config, core folders) and installs essential packages
- **MakeCommand**: Creates features, pages, forms, models, and adds languages
- **FiendCommand**: Finds unused assets, packages, and files
- **RunCommand**: Utility tasks like code formatting

### Core Components

#### Creators (lib/creatores.dart)
Central factory class containing static methods for generating project components:
- `init()`: Creates full project infrastructure (app, theme, config, core folders, splash/home features)
- `createFeature()`: Generates feature with bloc pattern (feature file, page, bloc, state)
- `addPage()`: Adds page to existing feature and updates feature routing
- `addLang()`: Adds localization support with .arb files
- `addForm()`: Creates forms with specified fields

#### CreatorUtil (lib/core/creator_util.dart)
Low-level file/directory operations:
- `createDirectory()`: Creates directories with logging
- `createFileWithContent()`: Creates files with optional Dart formatting
- `readFileContent()`: Reads file contents asynchronously
- `editFileContent()`: Updates existing files with optional formatting

#### Samples (lib/samples/)
Template files for code generation. Each sample function returns a string containing code templates with placeholder interpolation. Examples:
- `featureSample()`: Feature class with GoRouter integration
- `pageSample()`: Stateless widget page template
- `cubitSample()`, `stateSample()`: Bloc pattern templates
- `mainSample()`: Main.dart with app initialization
- `formSample()`: Form with TextFormField for each specified field

### Key Patterns

#### Feature Module Pattern
Each feature is self-contained with:
- **{feature}_feature.dart**: Feature class extending `AppFeature` from `app_features` package, contains GoRouter routes
- **{feature}_page.dart**: Main page widget
- **bloc/**: State management (Cubit/Bloc pattern)
- **pages/**: Additional pages for multi-page features
- **forms/**: Form widgets
- **actions/**: API actions/business logic

#### Code Generation Flow
1. User runs command with options
2. Command parses arguments via `argParser`
3. Command calls appropriate `Creators` method
4. `Creators` calls sample functions to get code templates
5. `CreatorUtil` writes formatted files to disk
6. For some operations (like adding pages), existing files are read, modified, and rewritten

#### Package Management
- **lib/core/constants/packages_name.dart**: Lists packages installed during `init`
- Essential packages: `app_features`, `api_request`, `flutter_bloc`, `go_router` (via app_features), `hive_flutter`, `get_it`, `responsive_framework`
- **lib/functions/install_package.dart**: Handles package installation via pub commands

### Utilities in lib/functions/
- **install_package.dart**: Runs `dart pub add` commands
- **run_pub_get.dart**: Executes `dart pub get`
- **formate_code.dart**: Formats Dart code using `dart format`
- **fiend_unused_*.dart**: Scans codebase for unused resources
- **extract_strings.dart**: String extraction utilities
- **add_action.dart**: Adds API actions to features

## Working with the Codebase

### Adding New Commands
1. Create command class in `lib/commands/` extending `Command`
2. Implement `name`, `description`, and `run()` method
3. Add `argParser` options in constructor
4. Register command in `bin/flyer.dart`

### Adding New Sample Templates
1. Create sample function in appropriate file under `lib/samples/`
2. Return formatted string with code template
3. Use string interpolation for dynamic values
4. Call sample from `Creators` methods

### Modifying Generated Structure
- Update sample templates in `lib/samples/`
- Modify `Creators.init()` for infrastructure changes
- Update `CreatorUtil` for file operation changes

### Code Formatting
All generated Dart code is automatically formatted using `DartFormatter` with latest language version. To disable formatting for specific files (like JSON/YAML), pass `canFormated: false` to file creation methods.

## Dependencies
- **args**: CLI argument parsing
- **dart_style**: Code formatting
- **yaml**: YAML parsing for pubspec manipulation
- **http**: HTTP requests for potential future features
